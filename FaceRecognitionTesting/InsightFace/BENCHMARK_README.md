# InsightFace multi-user benchmark

This benchmark has two manual stages. The first stage runs InsightFace and saves
embeddings, pair definitions, detection failures, and latency measurements. The
second stage reads only the generated files, calculates cosine similarities, and
writes the evaluation report.

## 1. Prepare the images

Use the reference filename (without its extension) as the user ID. The captured
image folder must use exactly the same ID.

```text
reference_images/
  user1.jpg
  user2.jpg
  user3.png

capture_images/
  user1/
    img_1.jpg
    img_2.jpg
  user2/
    img_1.jpg
    img_2.jpg
  user3/
    img_1.jpg
```

Each image must contain exactly one detectable face. Supported extensions are
`.jpg`, `.jpeg`, `.png`, `.bmp`, and `.webp`.

## 2. Generate embeddings and pairs

Open `GenerateBenchmarkData.py` and set `MODEL_PACK_NAME`. Then run:

```powershell
cd C:\smart-attendance-platform\FaceRecognitionTesting\InsightFace
..\..\.venv\Scripts\python.exe GenerateBenchmarkData.py
```

The script creates:

```text
benchmark_data/<model_pack>/
  benchmark_data.json
  genuine_pairs.json
  fake_pairs.json
```

- A genuine pair compares one user's reference embedding with that user's
  captured embedding.
- A fake/impostor pair compares one user's reference embedding with every
  successful captured embedding belonging to another user.
- Embeddings are stored once in `benchmark_data.json`. Pair files contain IDs
  that point to those embeddings, avoiding repeated 512-value vectors.
- Failed reads, no-face detections, and multiple-face detections are recorded
  for the detection-failure rate.

Cold-start latency is model initialization plus the first actual inference.
Warm-inference samples are all later calls to `FaceAnalysis.get()`. File reading
and cosine comparison are recorded separately from model inference.

## 3. Generate the report

Open `EvaluateBenchmark.py` and set:

```python
MODEL_PACK_NAME = "buffalo_l"
SIMILARITY_THRESHOLD = 0.60
```

The model name must match data previously generated by stage 1. The threshold is
experimental and should be calibrated using genuine and impostor score
distributions.

Run:

```powershell
..\..\.venv\Scripts\python.exe EvaluateBenchmark.py
```

Each evaluation creates timestamped, model-specific files:

```text
benchmark_reports/
  <model>_threshold_<threshold>_<timestamp>.json
  <model>_threshold_<threshold>_<timestamp>.txt
  <model>_threshold_<threshold>_<timestamp>_pair_scores.csv
```

The report includes:

- False acceptance rate (FAR): accepted fake pairs divided by all fake pairs.
- False rejection rate (FRR): rejected genuine pairs divided by all genuine pairs.
- True acceptance rate (TAR): accepted genuine pairs divided by all genuine pairs.
- Detection failure rate: images that failed to produce exactly one embedding
  divided by all attempted images.
- Cold-start latency.
- Mean warm-inference latency, plus median, p95, minimum, maximum, and sample count
  in the JSON report.

To test another model, change `MODEL_PACK_NAME` in the generation script and run
stage 1 again. Then select the same model and an appropriate threshold in the
evaluation script. Data and reports are separated by model name.

The generated folders are excluded from Git because face embeddings and image
identifiers are sensitive benchmark data.
